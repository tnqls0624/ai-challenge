# 돈워리 UX·콘텐츠 가이드

> 상태: 구현 기준 초안
>
> 관련 문서: [화면 IA](ia.md) · [사용자 조사](user-research.md) · [알림 정책](alert-policy.md)

## 1. 말투 원칙

- 불안을 키우지 않되 행동은 분명하게 말합니다.
- “사기입니다”처럼 확정하지 않고 “위험 신호가 확인되었습니다”라고 말합니다.
- 한 문장에는 한 행동만 둡니다.
- 사용자를 탓하거나 디지털 지식을 시험하지 않습니다.
- 전문 용어보다 실제 행동을 씁니다.
- 점수보다 근거와 다음 행동을 먼저 보여줍니다.

금지:

- “왜 누르셨나요?”
- “100% 보이스피싱입니다”
- “AI가 판단했습니다”
- “보호자에게 감시되고 있습니다”
- “정상입니다”라는 표현을 불충분한 데이터에 사용

권장:

- “확인이 더 필요합니다.”
- “지금은 송금하지 마세요.”
- “문자에 적힌 번호 말고 공식 번호로 확인하세요.”
- “확인 요청을 보내도 괜찮습니다.”

## 2. 위험 수준 표현

| Level | 사용자 제목 | 요약 | 기본 CTA |
|---|---|---|---|
| SAFE | 특이한 위험 신호가 없어요 | 확인한 범위에서는 뚜렷한 위험 신호가 없습니다 | 닫기 |
| CAUTION | 한 번 더 확인하세요 | 의심되는 부분이 있어 바로 행동하지 않는 것이 좋습니다 | 확인 요청 |
| HIGH | 지금 행동을 멈추세요 | 위험 신호가 확인되었습니다 | 보호자에게 확인 |
| CRITICAL | 지금 송금·설치를 멈추세요 | 여러 위험 신호가 함께 확인되었습니다 | 바로 전화하기 |
| UNKNOWN | 확인이 더 필요해요 | 가져오지 못했거나 확인하지 못한 정보가 있습니다 | 직접 확인 |

SAFE에서도 “안전이 보장됩니다”라고 말하지 않습니다.

## 3. 근거 문장

근거는 최대 3개이며 아래 순서를 사용합니다.

1. 행동 신호: 송금·설치·인증정보 요구
2. 출처 신호: 공식 domain·번호와 불일치, 신고 데이터
3. 맥락 신호: 직전 의심 문자와 전화 연관, 긴급·비밀 유지 압박

템플릿:

- “돈을 보내 달라는 요청이 있습니다.”
- “공식기관 주소와 다른 링크입니다.”
- “앱을 설치하고 화면을 보여 달라고 요구했습니다.”
- “조금 전 의심 문자와 이어진 전화일 수 있습니다.”
- “이 링크의 평판은 확인하지 못했습니다.”

근거에 없는 사실을 설명에 추가하지 않습니다.

## 4. 행동 문구

| 상황 | 첫 행동 | 다음 행동 |
|---|---|---|
| 의심 문자 | 링크를 열지 마세요 | 공식 앱·사이트에서 직접 확인 |
| 의심 전화 | 통화를 끊고 다시 확인하세요 | 문자 속 번호가 아닌 공식 경로 |
| 앱 설치 요구 | 설치하지 마세요 | 이미 설치했다면 사건 단계 확인 |
| 인증정보 요구 | 알려주지 마세요 | 계정·금융기관 보호 절차 확인 |
| 송금 요구 | 지금 송금하지 마세요 | 보호자 또는 금융기관에 별도 확인 |
| 이미 송금 | 추가 송금을 멈추세요 | S4 긴급 대응 체크리스트 |

긴급 대응 번호와 금융기관별 절차는 release 전에 공식 출처와 확인일을 기록한 콘텐츠만 사용합니다.

## 5. 보호자 알림

긴급 알림:

```text
김영희 어르신에게 매우 위험한 신호가 확인되었습니다.

유형: 공공기관 사칭 의심
시각: 오후 2:32
행동 신호: 송금 요구
상태: 아직 확인하지 않음

[바로 전화하기] [상황 보기]
```

일반 확인 요청:

```text
김영희 어르신이 문자 확인을 요청했습니다.

긴급 상황으로 확인되지는 않았지만,
함께 확인해 주세요.

[내용 확인]
```

긴급 알림과 일반 확인 요청은 색·아이콘·제목을 다르게 사용합니다.

## 6. 오류·부분 결과

| 상황 | 문구 |
|---|---|
| 알림 본문 없음 | 문자 내용을 가져오지 못했습니다. 공유하거나 붙여넣어 확인할 수 있습니다. |
| 네트워크 없음 | 먼저 휴대전화에서 확인했습니다. 연결되면 추가 확인 결과를 알려드립니다. |
| 평판 API 실패 | 링크 평판은 확인하지 못했습니다. 다른 위험 신호를 기준으로 안내합니다. |
| LLM 실패 | 분석은 완료되었습니다. 확인된 근거를 그대로 안내합니다. |
| push 실패 | 사건은 저장되었지만 보호자 알림 전송을 확인하지 못했습니다. |
| 권한 거부 | 자동 확인은 꺼져 있습니다. 직접 확인 기능은 계속 사용할 수 있습니다. |

오류 코드와 내부 서비스명을 사용자 화면에 노출하지 않습니다.

## 7. S0~S4 콘텐츠

| 단계 | 제목 | 첫 행동 |
|---|---|---|
| S0 행동 전 | 아직 행동하지 않았다면 멈춰주세요 | 링크·통화 중단 |
| S1 링크 클릭 | 다운로드된 파일이 있는지 확인하세요 | 추가 입력·설치 중단 |
| S2 개인정보 입력 | 계정과 금융정보를 보호하세요 | 비밀번호 변경·기관 확인 |
| S3 앱 설치 | 휴대전화 연결을 잠시 끊으세요 | 네트워크 차단·앱 점검 |
| S4 송금 완료 | 추가 송금을 멈추고 즉시 조치하세요 | 신고·지급정지 절차 시작 |

각 화면은 현재 단계에서 가장 중요한 행동 하나를 먼저 보여주고 전체 체크리스트는 다음 화면에 둡니다.

## 8. 접근성

- Android 본문 기본 18sp 이상
- 핵심 버튼 높이 56dp 이상
- 한 화면의 핵심 CTA 하나
- 색 외에 텍스트·아이콘·형태로 상태 표현
- 동적 글자 확대에서 잘림 없음
- TalkBack·screen reader label 제공
- focus 순서는 제목 → 결과 → 근거 → CTA
- 카운트다운만으로 선택을 강제하지 않음
- 진동·소리는 OS 설정을 존중하고 끌 수 있는 경로 제공
- 웹은 키보드만으로 모든 대응 기능 수행

## 9. 검수 체크

- 사용자에게 책임을 돌리는 표현이 없는가?
- 위험을 확정적으로 단정하지 않는가?
- 첫 화면에서 “지금 무엇을 해야 하는가”를 알 수 있는가?
- 근거가 RiskSignal에 실제 존재하는가?
- MINIMAL 공유 수준에서 과도한 정보가 보이지 않는가?
- UNKNOWN이 SAFE처럼 보이지 않는가?
- 긴급과 일반 확인 요청이 구분되는가?
- 큰 글씨와 screen reader에서 의미가 유지되는가?
