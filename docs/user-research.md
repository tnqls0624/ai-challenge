## 1. 페르소나

### 1-1. 보호 대상자 — 김영희 (65세)

> **한 문장**: 스마트폰은 쓸 줄 알지만, 압박받는 상황에서 "잠시만요"라고 말하지 못하는 사람.

| 항목 | 내용 |
|---|---|
| **나이·거주** | 65세, 배우자와 2인 거주. 자녀는 타지역 |
| **직업** | 은퇴 (前 자영업). 국민연금·예금 이자 생활 |
| **자산 특성** | 노후 자금이 소수 계좌에 집중. **한 번의 피해가 전체 손실로 이어짐** |
| **디지털 숙련도** | 카카오톡·문자·은행 앱 사용 가능. 앱 설치와 인증 절차도 수행 가능 |

**행동 특성**

- 공공기관·금융기관이라는 말에 **기본적으로 신뢰**를 부여함
- 문자는 **알림창에서 바로 확인**. 앱을 따로 열지 않음
- 모르는 번호도 **일단 받음** ("중요한 전화일 수 있으니")
- 자녀에게 연락할 때 **"바쁜데 괜히 귀찮게 하는 것"** 을 우려함

**위험 순간의 실제 행동**

```
문자 수신 → 알림창에서 읽음 → 불안해짐 → 링크를 누름
                                    ↓
                          "확인해봐야겠다"는 판단은 하지만
                          확인할 방법을 모름 (검색 대신 문자 속 번호로 전화)
```

| 취약 지점 | 설명 |
|---|---|
| **권위 신뢰** | "검찰청입니다"에 의심을 갖지 않음 |
| **압박 하 판단 정지** | 통화 중에는 생각할 시간을 확보하지 못함 |
| **검증 경로 부재** | 공식 대표번호를 찾는 방법을 모름. 문자 속 번호를 그대로 사용 |
| **고립 유도에 취약** | "가족에게 말하지 말라"는 지시를 따름 |

**주요 위험 시나리오**: 기관 사칭 → 원격제어 앱 설치 → 안전계좌 송금

**서비스에 대한 요구**

| 요구 | UI 반영 |
|---|---|
| 큰 글씨 | 본문 최소 18sp |
| 쉬운 문장 | "위험도 91점" ❌ → "매우 위험" ✅ |
| 한 번에 하나의 행동 | 한 화면에 핵심 CTA 1개 |
| 이유를 알고 싶음 | 근거 최대 3줄 |
| 누르기 쉬운 버튼 | 버튼 높이 최소 56dp |

**디자인 제약**

- 노안으로 작은 글씨 판독이 어려움 → 폰트 크기·대비 확보 필수
- 색상만으로 구분하는 UI는 인지되지 않을 수 있음 → **아이콘·텍스트 병행**
- 실수로 뒤로 가기를 누르는 경우가 있음 → **위험 안내가 즉시 사라지지 않아야 함**
- 긴 안내문은 읽지 않음 → 3줄 이내

### 1-2. 보호자 — 이수빈 (35세)

> **한 문장**: 부모를 걱정하지만 감시하고 싶지는 않고, 정작 필요한 순간에는 아무것도 모르는 사람.

| 항목 | 내용 |
|---|---|
| **나이·관계** | 35세, 김영희의 자녀. 타지역 거주 |
| **직업** | 직장인. 근무 시간 대부분 **데스크톱 환경** |
| **연락 빈도** | 주 1~2회 통화. 매일 확인하지는 못함 |
| **디지털 숙련도** | 높음. 앱 설치·설정에 거부감 없음 |

**현재 겪는 문제**

```
[현재]  부모가 문자 수신 → 통화 → 앱 설치 → 송금 → ... → 며칠 뒤 자녀가 알게 됨
                                                              ↑
                                                     이미 회복 불가능한 시점

[돈워리]  부모가 문자 수신 → 위험 판정 → 즉시 알림 → 자녀가 전화
                                              ↑
                                     행동 전환 이전 시점
```

**행동 특성**

- 알림을 받으면 **즉시 확인**하지만, 근무 중이라 긴 내용은 읽지 못함
- 부모에게 전화하기 전에 **"무슨 상황인지"** 를 30초 안에 파악하고 싶어함
- 부모의 문자 내용을 **다 보고 싶어하지는 않음** — 죄책감과 부담을 느낌

**요구와 우려의 균형**

| 요구 | 우려 |
|---|---|
| 위험 상황 즉시 확인 | 부모의 사생활을 침해하고 싶지 않음 |
| 부모에게 바로 전화 | 부모가 "감시당한다"고 느끼는 것을 원치 않음 |
| 무슨 일인지 파악 | 문자 원문 전체를 보는 것은 과하다고 생각 |
| 대응 방법 안내 | 자신도 무엇을 해야 하는지 모름 |

> **설계 함의**: 이 긴장 관계가 **공유 수준 3단계(최소/기본/확장)** 설계의 근거입니다.
> 기본값은 "마스킹된 정보 + 위험 유형"이며, 원문 공유는 보호 대상자의 별도 승인이 필요합니다.

**서비스에 대한 요구**

| 요구 | UI 반영 |
|---|---|
| 앱 설치 없이 확인 | **웹 URL 접속만으로** 사용 가능 |
| 30초 안에 상황 파악 | 위험 유형·시각·행동 신호를 한 화면에 |
| 즉시 전화 | **[바로 전화하기]** 버튼 고정 배치 |
| 데스크톱 사용 | 반응형 웹, 데스크톱 우선 레이아웃 |

### 1-3. 심사위원 (대회 평가자)

> **한 문장**: Android 기기 없이, 웹 URL 하나로 서비스의 실체를 판단해야 하는 사람.

| 요구 | 제품 대응 | 관련 제출물 |
|---|---|---|
| 설치 없이 서비스 확인 | 공개 웹 데모 (로그인 불필요) | 기능명세서 3번 |
| AI의 필요성 확인 | 다중 신호 분석과 근거 표시 | 기획서 5번 |
| 데이터 출처 확인 | 데이터 카드와 출처·기준일 표시 | 기획서 5번 |
| 실제 구현 여부 확인 | Android 기기와 웹 동시 데모 | 기능명세서 2번 |
| 안전성·규제 검토 | 동의·마스킹·최소수집 구조 | 기능명세서 4번 |
| 기술 검증 | 평가 대시보드와 테스트 결과 | 기능명세서 5번 |

**심사위원 여정 (웹 데모)**

```
URL 접속 → 시나리오 선택 → 가상 문자 수신 → 분석 과정 확인
   → 위험 근거 확인 → 연관 전화 발생 → 가족 알림 확인
   → 피해 단계 선택 → 대응 체크리스트 → 평가 결과 확인
```

> **설계 제약**: 심사위원은 **설명을 듣지 못한 상태**로 접속합니다.
> 각 화면에 "지금 무엇을 보고 있는지"가 자체적으로 설명되어야 합니다.

## 2. 사용자 여정

각 여정은 **사용자 행동 / 시스템 동작 / 사용자 감정 / 이탈 위험 / 서비스 개입**의 5개 축으로 기술합니다.

---

### 2-1. 스미싱 예방 여정 (김영희)

**상황**: 오후 2시, 건강보험공단을 사칭한 미납 안내 문자 수신

| 단계 | 사용자 행동 | 시스템 동작 | 사용자 감정 | 이탈 위험 |
|---|---|---|---|---|
| 1 | 알림창에서 문자 확인 | NotificationListener가 본문 추출 | 😟 불안 | — |
| 2 | — | URL·전화번호·위험 표현 추출 | | |
| 3 | — | 기기 내 1차 규칙 분석 | | |
| 4 | — | 서버에서 URL 평판 조회 (KISA·Safe Browsing) | | |
| 5 | **위험 경고 확인** | 최종 위험 수준 생성 → 경고 화면 표시 | 😨 놀람 | ⚠️ **경고를 닫고 링크를 누를 수 있음** |
| 6 | 근거 3줄 읽음 | 판단 근거 + 지금 할 일 표시 | 🤔 이해 | ⚠️ 근거가 어려우면 무시 |
| 7 | **[가족에게 확인 요청]** 누름 | 보호자에게 FCM + 웹 알림 발송 | 😌 안도 | ⚠️ "귀찮게 하는 것 같아" 주저 |
| 8 | 자녀의 전화 받음 | 보호자가 상황 확인 후 전화 | 😊 안심 | — |
| 9 | 사건 안전 종료 | 사건 상태 RESOLVED 기록 | | |

**핵심 개입 지점**

| 지점 | 개입 내용 | 설계 요구 |
|---|---|---|
| **5단계** | 링크 클릭 이전에 경고 | 경고가 **알림보다 먼저** 보여야 함. 뒤로 가기로 즉시 사라지지 않아야 함 |
| **6단계** | 이해 가능한 근거 제공 | 전문용어 금지. "공식기관과 다른 주소입니다" 수준 |
| **7단계** | 가족 연결의 심리적 장벽 해소 | "확인 요청"은 부담을 낮추는 표현. "신고"나 "도움 요청"보다 가벼움 |

> **가장 중요한 설계 판단 (7단계)**
> 김영희는 자녀를 귀찮게 하는 것을 우려합니다. 버튼 문구가 **"도와주세요"** 면 누르지 않고, **"가족에게 확인 요청"** 이면 누릅니다. 같은 기능이라도 문구가 전환율을 결정합니다.

### 2-2. 보이스피싱 예방 여정 (김영희)

**상황**: 스미싱 문자 30분 후, 주소록에 없는 번호로 전화 착신

| 단계 | 사용자 행동 | 시스템 동작 | 사용자 감정 | 이탈 위험 |
|---|---|---|---|---|
| 1 | 전화 착신 | CallScreeningService가 발신번호 확인 | 😐 평온 | — |
| 2 | — | 자체 번호 DB·신고 데이터 조회 | | |
| 3 | — | **직전 의심 문자와 시간적 연관성 확인** | | |
| 4 | **위험 전화 경고 확인** | 위험 수준 격상 → 경고 표시 | 😟 경계 | ⚠️ 경고를 무시하고 통화할 수 있음 |
| 5 | 통화함 (또는 거절) | — | 😰 압박 | ⚠️ **통화 중에는 개입 불가** |
| 6 | **통화 후 설문 응답** | 행동 신호 질문 표시 | 🤔 회상 | ⚠️ 설문을 건너뛸 수 있음 |
| 7 | "앱 설치 요구" + "송금 요구" 선택 | **CRITICAL 판정** | 😨 인지 | — |
| 8 | 가족 알림 발송 확인 | 보호자에게 즉시 알림 | 😌 안도 | — |
| 9 | 보호 모드 안내 확인 | **30분 송금주의 보호 모드** 활성화 | | |
| 10 | 공식 대표번호로 재확인 | 공식기관 번호 안내 | 😊 안심 | — |

**핵심 개입 지점**

| 지점 | 개입 내용 | 설계 요구 |
|---|---|---|
| **3단계** | 문자–전화 연관 분석 | 단독 신호로는 CAUTION → 연관 확인 시 **HIGH 이상 격상** |
| **5단계** | **통화 중에는 개입할 수 없음** | 서비스의 구조적 한계. 통화 전·후에 집중 |
| **6단계** | 설문 응답률 확보 | 통화 종료 직후 자동 표시. 4~6개 체크박스 이내 |
| **9단계** | 송금 직전 마지막 방어선 | 30분간 위험 안내 유지 |

> **여정 2-1과 2-2의 연결이 서비스의 핵심입니다.**
> 두 여정은 **같은 사건의 1막과 2막**입니다. 문자만 보면 흔한 스미싱이고 전화만 보면 모르는 번호지만, 30분 간격으로 이어지면 명백한 기관 사칭 시나리오입니다. 이 연결을 판정에 쓰는 것이 기존 서비스와의 차별점입니다.

### 2-3. 피해 발생 여정 (김영희 + 이수빈)

**상황**: 이미 송금이 완료된 상태에서 서비스에 진입

| 단계 | 사용자 행동 | 시스템 동작 | 사용자 감정 | 설계 요구 |
|---|---|---|---|---|
| 1 | **"이미 송금함" 선택** | 피해 단계 S4 판정 | 😱 공황·수치심 | **비난하지 않는 문구** |
| 2 | — | 긴급 대응 모드 전환 | | 화면 전체를 대응 절차로 전환 |
| 3 | 112 신고 안내 확인 | 신고 절차 안내 | 😖 혼란 | **한 번에 하나씩** 제시 |
| 4 | 금융회사 지급정지 안내 확인 | 해당 금융회사 연락처 표시 | | 전화 연결 버튼 직접 제공 |
| 5 | 증거 보존 안내 확인 | 문자·전화 이벤트 보존 | | 자동 보존, 사용자 조작 최소화 |
| 6 | — | **사건 경위 자동 요약 생성** (LLM) | 😌 안도 | 신고 시 그대로 사용 가능한 형태 |
| 7 | 가족과 대응 항목 분담 | 보호자 웹에 체크리스트 공유 | | 누가 무엇을 할지 명확히 |
| 8 | 조치 완료 기록 | 상태 업데이트 | | |

**이 여정의 특수성**

| 고려사항 | 설계 반영 |
|---|---|
| **사용자는 공황 상태** | 선택지를 최소화. 한 화면에 하나의 행동만 |
| **수치심으로 가족에게 알리기 어려움** | "가족에게 알리기"를 강요하지 않되, 권장 |
| **시간이 가장 중요** | 지급정지는 골든타임이 존재. 절차를 가장 앞에 |
| **사용자가 스스로 설명하기 어려움** | LLM이 사건 경위를 대신 요약 |

> **문구 설계 원칙 (1단계)**
> "왜 송금하셨나요" 같은 표현은 절대 사용하지 않습니다. 사용자는 이미 자책하고 있으며, 서비스가 비난하면 즉시 이탈합니다.
> **"지금 바로 해야 할 일이 있습니다"** — 과거가 아니라 다음 행동으로 시선을 옮깁니다.

### 2-4. 보호자 여정 (이수빈)

**상황**: 근무 중 데스크톱에서 부모의 위험 알림 수신

| 단계 | 사용자 행동 | 시스템 동작 | 소요 목표 |
|---|---|---|---|
| 1 | 알림 수신 (FCM / 웹) | 고위험 사건 발생 시 즉시 발송 | 즉시 |
