## 1. 채널

```text
돈워리
├─ Android 보호 앱
│  ├─ 활성화·권한
│  ├─ 문자·URL 검사
│  ├─ 전화 경고·통화 후 설문
│  ├─ 사건 대응
│  └─ 설정·동의
├─ 보호자 웹
│  ├─ 로그인
│  ├─ 1:25 대시보드
│  ├─ 대상자·활성화
│  ├─ 사건 대응
│  └─ 알림·공유 설정
└─ 심사위원 웹 데모
   ├─ 제품 설명
   ├─ 시나리오 선택
   ├─ 분석 재생
   └─ 대응·평가 결과
```

## 2. Android 화면

| ID | 화면 | 핵심 목적 | 핵심 CTA |
|---|---|---|---|
| `A01` | 시작·활성화 코드 | 대상자 계정 없이 기기 연결 시작 | 코드 확인 |
| `A02` | 연결·동의 확인 | 보호자, 공유 수준, 자동 알림 동의 | 연결 승인 |
| `A03` | 권한 센터 | 알림 접근·전화 스크리닝·알림 권한을 개별 설명 | 다음 권한 설정 |
| `A04` | 홈 | 보호 상태·권한·최근 사건 확인 | 문자 직접 확인 |
| `A05` | 문자 입력 | 공유·붙여넣기·URL 입력 | 위험 확인 |
| `A06` | 분석 중 | 로컬 결과와 서버 확인 상태 표시 | 취소/백그라운드 |
| `A07` | 위험 결과 | 위험 수준, 근거 최대 3개, 지금 할 행동 | 확인 요청 또는 공식 경로 |
| `A08` | 전화 경고 | 통화 전 위험 근거와 행동 제동 | 통화 거절/알림 닫기 |
| `A09` | 통화 후 설문 | 송금·설치·인증정보·사칭 신호 수집 | 결과 확인 |
| `A10` | 사건 대응 | S0~S4 단계와 체크리스트 | 다음 행동 완료 |
| `A11` | 보호자 연결 | 연결 보호자·공유 수준 확인 | 설정 변경/연결 해제 |
| `A12` | 설정·개인정보 | 프리셋, 동의, 데이터 삭제, 기기 해제 | 변경 저장 |

### Android 흐름

```text
A01 코드
  → A02 연결·동의
  → A03 권한 센터
  → A04 홈

Notification/Share/Manual
  → A06 분석 중
  → A07 위험 결과
  ├─ 확인 요청
  └─ A10 사건 대응

Incoming call
  → A08 전화 경고
  → 통화 종료
  → A09 설문
  → A07/A10
```

권한을 거부해도 활성화 전체를 실패 처리하지 않습니다. 해당 자동 기능만 비활성화하고 A04에서 대체 입력을 제공합니다.

## 3. 보호자 웹

| ID | Route | 화면 | 핵심 목적 |
|---|---|---|---|
| `W01` | `/login` | 보호자 로그인 | Firebase 로그인 |
| `W02` | `/dashboard` | 1:25 대시보드 | 누구부터 확인할지 판단 |
| `W03` | `/subjects/new` | 대상자 등록 | 최소 프로필 생성 |
| `W04` | `/subjects/:id/activate` | 활성화 코드 | 10분 코드 표시·재발급 |
| `W05` | `/subjects/:id` | 대상자 상세 | 최근 위험·연결·권한 상태 |
| `W06` | `/incidents/:id` | 사건 상세 | 위험 근거·행동 신호·현재 대응 |
| `W07` | `/incidents/:id/actions` | 체크리스트 | 담당·완료 기록 |
| `W08` | `/settings/notifications` | 알림 설정 | threshold·웹 푸시 상태 |
| `W09` | `/settings/privacy` | 공유·연결 | 자신의 수신 설정과 연결 해제 |

### 대시보드 정보 우선순위

1. `CRITICAL` 우선
2. 송금·앱 설치·비밀정보 요구 신호
3. 미대응 시간
4. 발생 시각
5. 이미 대응 완료한 사건은 하향

카드 한 장에 이름, 위험 수준, 유형, 발생 시각, 행동 신호, 상태, 전화 CTA를 표시합니다. 문자 원문은 목록에 표시하지 않습니다.

P0 W06에는 문자 원문을 표시하지 않습니다. P1에서 `EXTENDED`를 구현할 때만 “15분 안에 한 번 확인” CTA와 만료·철회 상태를 추가합니다.

## 4. 심사위원 웹 데모

| ID | Route | 화면 | 핵심 목적 |
|---|---|---|---|
| `D01` | `/demo` | 제품 소개 | 설치 없이 가치 이해 |
| `D02` | `/demo/scenarios` | 6개 시나리오 | 체험 흐름 선택 |
| `D03` | `/demo/scenarios/:scenarioId` | 시나리오 재생 | 문자→전화→설문→대응 |
| `D04` | `/demo/evaluation` | 평가 설명 | 데이터·규칙·실측 결과 |

데모 상태는 브라우저 `sessionStorage`에만 저장합니다. 데모 화면에 “합성 데이터이며 실제 알림을 발송하지 않습니다”를 항상 표시합니다.

## 5. 공통 화면 상태

모든 데이터 화면은 다음 상태를 설계합니다.

| 상태 | 필수 표현 |
|---|---|
| Initial | 다음 행동 하나 |
| Loading | 무엇을 확인 중인지, 예상보다 길 때 대체 경로 |
| Empty | 정상 상태인지 설정이 필요한지 구분 |
| Success | 결과·근거·다음 행동 |
| Partial | 확인하지 못한 항목과 로컬 결과 |
| Error | 사용자 탓으로 표현하지 않는 오류와 재시도 |
| Offline | 임시 결과, 저장·재전송 여부 |
| Permission denied | 기능 영향과 수동 대체 경로 |
| Consent revoked | 이후 공유·알림이 중단됨을 명시 |

## 6. 위험 결과 정보 구조

```text
[위험 수준 + 텍스트]
[한 문장 요약]

왜 이렇게 판단했나요?
1. 근거
2. 근거
3. 근거

[지금 할 행동 하나]
[보호자 확인 요청 또는 공식기관 확인]

상세: 데이터 출처·확인하지 못한 항목·정책 버전
```

색상만으로 위험도를 구분하지 않습니다. 점수보다 위험 수준과 행동을 먼저 표시합니다.

## 7. 전화 경고 제약

- P0 기본은 고우선순위 알림입니다.
- 사용자가 알림을 누르면 A08로 이동합니다.
- 전체화면 intent는 실기기에서 허용된 조합에만 사용합니다.
- CallScreening 응답은 네트워크 결과를 기다리지 않습니다.
- 자동 차단은 등록된 데모 번호에서만 허용합니다.

## 8. Figma handoff

각 Figma frame 이름을 화면 ID로 시작합니다.

```text
A07 Risk Result / CRITICAL / Default
A07 Risk Result / UNKNOWN / Partial
W02 Dashboard / Mobile / Multiple Critical
D03 Demo Scenario / Government Impersonation / Step 3
```

handoff 시 포함:

- Default/Loading/Empty/Error/Offline
- 360px 모바일과 desktop
- 큰 글씨·텍스트 확대
- focus·TalkBack 순서
- CTA disabled 이유
- 실제 문구와 placeholder 구분

## 9. IA 완료 조건

- 모든 P0 기능이 화면 또는 명시적 background 동작에 연결됨
- 권한 거부·오프라인·외부 API 장애 화면 존재
- 대상자 25명과 다중 CRITICAL 상태 설계
- P0 MINIMAL/BASIC별 정보 차이 확인
- P1 구현 시 원문 grant의 열기 전 확인·1회 조회·만료·철회 상태 확인
- S0~S4 단계별 다음 행동 확인
- 데모 6개 시나리오가 같은 route 구조로 완주
- Android 화면 ID와 Compose route가 매핑
- 웹 화면 ID와 Next.js route가 매핑
